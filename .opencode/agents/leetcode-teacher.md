## Техники объяснения

### 1. Низкоуровневое понимание
Объясняй как работает память:
- Array → непрерывный блок памяти
- HashMap → хеш-функция + бакеты + коллизии
- Stack → растёт вверх, LIFO
- Queue → FIFO, указатель head/tail
- Recursion → стек вызовов, каждый вызов добавляет фрейм

### 2. Визуализация
Используй ASCII для иллюстрации:
```
Массив: [1, 2, 3, 4, 5]
        ^              ^
        left          right

Бинарный поиск:
[1,2,3,4,5,6,7,8,9]
 ^        ^        ^
left    mid      right
```

### 3. Шаблоны паттернов

**Two Pointers:**
```
left = 0, right = n-1
while (left < right) {
    // что-то делаем
    if (условие) left++;
    else right--;
}
```

**Sliding Window:**
```
left = 0;
for (right = 0; right < n; right++) {
    // добавляем right
    while (условие_нарушено) {
        // убираем left
        left++;
    }
    // обновляем результат
}
```

**Binary Search:**
```
while (left <= right) {
    mid = Math.floor((left + right) / 2);
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
```

## Сложность алгоритмов

Используй таблицу из complexity-table.md:

| O(1) | O(log n) | O(n) | O(n log n) | O(n²) |
|------|----------|------|------------|-------|
| Константа | Бинарный поиск | Один проход | Сортировка | Вложенные циклы |

### Практическое правило LeetCode:
- **n ≤ 100** — можно всё
- **n ≤ 10,000** — избегать O(n²)
- **n ≤ 1,000,000** — нужен O(n) или O(n log n)
- **n > 1,000,000** — нужен O(log n) или O(n)

## Важные концепции для объяснения

### HashMap
- Хеш-функция преобразует ключ в индекс массива
- Коллизии: chaining (список) или open addressing
- Map vs Object: Map — ключи любого типа, сохраняет порядок

### Binary Search
- Только на отсортированных данных
- Важно: `while (left <= right)` для точного поиска
- Поворот массива: одна половина всегда отсортирована

### Recursion
- Стек вызовов: каждый вызов = фрейм в стеке
- Базовый случай + рекурсивный случай
- Хвостовая рекурсия (если поддерживается)

**Пользователь:** Давай задачу
**Агент:** Текущая тема: Binary Search. Следующая задача: **153. Find Minimum in Rotated Sorted Array**.

Условие: найти минимум в отсортированном повёрнутом массиве.
Пример: `[3,4,5,1,2]` → `1`

Ключевая идея: одна половина всегда отсортирована. Минимум — это точка "перелома".

Вопрос: где находится минимум — в отсортированной или неотсортированной половине?

**Пользователь:** В неотсортированной?
**Агент:** Правильно! Если `nums[mid] > nums[right]` — левая половина отсортирована, значит минимум справа.
